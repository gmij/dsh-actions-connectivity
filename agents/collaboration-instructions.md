# 智能体协作与知识沉淀规范

本规范由可信运行器注入 DSH 的实际任务提示词。原生 Copilot 仍仅负责 MCP 调度。

## 三个位置的职责

- **Discussions：讨论过程。** 用于需求澄清、方案比较、设计取舍、开放问题及阶段交流。同一主题尽量复用一条讨论，区分事实、假设、提案、已确认决定；阶段总结包含共识、分歧、待确认项与下一步。
- **Issues：可执行任务及结果。** 沉淀已确认的需求、范围、不做的事情、输入资料、验收条件、指定 Agent、依赖及里程碑。执行状态、产物、验证证据和最终结论以 Issue 为准。关联来源 Discussion，并将关键已确认结论写进正文，不能只有链接。
- **Wiki：长期设计知识。** 保存概要、详细设计、模块说明、输入输出契约及设计决策依据。提供目录、侧栏、最新版本与历史版本；关联来源 Issue。模块拆分时，同轮更新概要的模块章节。

## 从讨论到执行

讨论形成明确共识后，由人确认并创建或更新 Issue；没有明确确认时，只能提出结论草案和待确认问题。不能把模型建议、沉默或讨论帖子存在本身视为批准。

启动边界仍是 Issue 原生 Assign to Agent 中选择指定 Agent。发布 Discussion、回复讨论或发布 Wiki 本身不启动 DSH。任务完成后回写原 Issue，附 Wiki/原型 Pages/运行记录等真实链接，再由负责人按验收条件确认关闭。

执行过程中出现影响范围、接口、数据所有权或验收的重大问题，应在结果中列出建议讨论的主题、选项与取舍。未确认的设计明确标为提案，避免将其写成业务已接受的最终决定。设计产物完成和业务验收通过是两个不同状态。

## 当前能力边界与输出方式

当前 DSH 禁用执行工具，读取本 Issue 和有限仓库快照，不会自动抓取 Discussion 或其他 Issue 的链接正文。请将已确认结论粘贴到 Issue，或放入仓库可读文件。链接只是关联，不能当作已读取内容。

当前运行器自动回写 Issue，设计发布器同步 Wiki，原型发布器同步 Pages；尚未自动创建或回复 Discussions。需要讨论时，输出可复制的讨论建议和待确认项，不能声称已发帖、已创建子 Issue、已批准或已修改仓库文件。

原型和设计角色继续严格遵守其 JSON 输出契约，不添加契约外字段。讨论建议、来源、确认状态与待确认问题写在既有 Markdown 字段里；审查角色可直接分段说明。不要把用户日常聊天或原始会话记录自动搬运到公开仓库。

## 建议模板

Discussion：背景与目标 / 已知事实 / 候选方案与取舍 / 待确认问题 / 当前共识 / 关联 Issues。

Issue：已确认需求 / 来源 Discussion / 范围与非目标 / 输入与约束 / 指定 Agent / 依赖与里程碑 / 验收条件 / 完成结果及证据。

Wiki：范围与基线 / 架构与模块导航 / 模块详细设计 / 任务输入输出 / 设计模式及选择依据 / 概要同步修订 / 来源 Issue 与历史版本。
